# 종말 라디오 — 가중치·연계·천장 버전

GitHub Pages 자동 배포 설정을 포함합니다. 처음 올릴 때는 [GITHUB-PAGES.md](GITHUB-PAGES.md)를 참고하세요.

## 실행 / 업로드

프로젝트 폴더에서 `python3 -m http.server 8080 --directory dist` 실행 후 `http://localhost:8080` 접속. HTML 파일 더블클릭 대신 HTTP 서버로 실행하세요.
배포 대상은 `dist` 내부 파일 전체입니다. 업로드용 ZIP은 index.html이 최상단에 있습니다. 정적 사이트 호스팅에 해당 파일들을 업로드하면 됩니다.

## 용어와 흐름

- **이벤트**: 라디오에서 조우하는 방송 한 편. 가중치와 천장을 보유합니다.
- **행동 선택지**: 이벤트 안에서 플레이어가 누르는 버튼. 완료 조건, 천장 시작, 수집품 획득을 트리거합니다.
- 수신 시작 → 쿨타임 → 이벤트 추첨 및 표시 → 행동 선택 → 결과 기록 → 다음 쿨타임.
- 선택할 때까지 자동으로 넘어가지 않습니다. 기본적으로 이벤트는 반복 등장합니다.
- `once: true`인 이벤트는 행동 선택을 완료한 뒤 추첨에서 제외합니다. 현재 후보가 없으면 수신을 종료합니다.

## 데이터 작성: dist/events.js

```js
export const settings = { cooldownSeconds: 15 };
export const collectibles = [
  { id: 'map', name: '지도', description: '수집품 설명' },
];
export const events = [
  {
    id: 'intro', weight: 10,
    frequency: '89.1', title: '첫 방송', text: '방송 내용',
    choices: [
      {
        id: 'follow', text: '신호를 따라간다', result: '행동 결과',
        grantItems: ['map'],       // 선택 시 수집품 획득
        startPity: ['follow-up'],  // 선택 시 지정 이벤트의 천장 시작
      },
      { id: 'ignore', text: '머무른다', result: '다른 결과' },
    ],
  },
  {
    id: 'follow-up', weight: 3, once: true,
    requires: { choices: ['intro:follow'] },
    pity: { start: 'trigger', count: 3 },
    frequency: '104.7', title: '후속 방송', text: '방송 내용',
    choices: [{ id: 'ok', text: '응답한다', result: '결과' }],
  },
];
```

## 가중치 / 선행 조건

- 일반 추첨 확률 = 해당 이벤트 `weight` / 현재 등장 가능한 이벤트들의 `weight` 합.
- `weight: 0`은 추첨 제외입니다. 가중치는 0 이상의 유한한 숫자로 작성하세요.
- `requires: { events: ['intro'] }`: 해당 이벤트에서 아무 행동이나 선택 완료하면 해금.
- `requires: { choices: ['intro:follow'] }`: 해당 이벤트의 특정 행동을 선택 완료하면 해금.
- 여러 조건을 쓰면 **모두** 충족해야 합니다. 충족 전 유효 가중치는 0, 충족 후 원래 `weight`로 복원합니다.
- `requires` 생략 시 처음부터 해금됩니다. `pity.start: 'trigger'`만으로 이벤트가 잠기지는 않습니다. 트리거 전 조우도 막으려면 선행 조건을 함께 쓰세요.

## 천장 규칙

- 게임 시작 천장: `pity: { start: 'gameStart', count: 4 }`.
- 행동으로 시작: `pity: { start: 'trigger', count: 2 }`를 대상 이벤트에 쓰고 다른 행동의 `startPity`에 대상 id를 지정합니다.
- 카운트는 초가 아니라 **일반 이벤트의 등장 횟수**입니다. 선택을 기다리는 동안 줄지 않습니다.
- 카운트 2의 경우: 일반 등장(2→1) → 일반 등장(1→0) → 다음 방송에서 천장 대상 등장.
- 카운트 0으로 시작하면 다음 방송부터 강제 후보가 됩니다.
- 천장 0인 **해금된** 대상이 있으면 일반 이벤트는 제외하고 해당 대상들끼리 가중치 추첨합니다.
- 천장 강제 등장 회차에는 모든 활성 천장의 카운트가 줄지 않습니다. 동시에 0이 된 나머지 대상은 다음 방송에서도 강제 후보로 남습니다.
- 선행 조건이 잠겨 있으면 카운트가 0이어도 해금 전에는 등장하지 않습니다. 잠겨 있는 동안에도 일반 방송 등장에 따라 카운트는 줄어듭니다.
- 천장 대상이 일반 추첨에서 먼저 등장하면 해당 천장은 달성 처리합니다.
- 각 천장은 게임당 한 번만 시작합니다. 같은 트리거를 반복해도 초기화하거나 다시 시작하지 않습니다.
- 기본 가중치 0인 이벤트는 천장에서도 제외됩니다. 연계 이벤트는 양수 가중치와 `requires`로 설정하세요.

## 설정과 수집품

- 설정 창에서 기본 간격(1–3,600초)과 배속(0.5·1·2·4·8배)을 변경할 수 있습니다.
- 간격 변경은 다음 대기부터 적용됩니다. 배속은 남은 시간에도 즉시 반영됩니다.
- 설정 창 또는 수집품 창이 열려 있는 동안 쿨타임이 멈춥니다. 닫기 버튼과 Escape 모두 재개합니다.
- 수동 일시정지 상태에서 창을 여닫아도 수동 정지는 유지됩니다.
- 창을 열어 둔 채 새로고침하면 창은 닫히고 저장된 남은 시간부터 재개합니다. 수동 정지는 유지됩니다.
- `grantItems`로 지정한 수집품을 획득합니다. 같은 물건은 하나만 보유합니다.
- 미발견 수집품의 이름과 설명은 확인 창에서 가려집니다. 획득 결과는 수신 기록에도 표시됩니다.
- **수신 설정 → 진행 리셋**으로 기록, 완료 조건, 수집품, 천장을 초기화합니다. 간격·배속 설정은 유지합니다. 쿠키 삭제는 필요 없습니다.

## 저장 / 검증

진행은 브라우저 localStorage에 저장됩니다. 기기 간 동기화는 없습니다. 일반 대기 중 탭을 닫아도 실제 시간이 흐르며, 돌아오면 방송 하나만 도착합니다. 확인 창 또는 수동 일시정지 중에는 남은 시간이 보존됩니다.
이벤트·수집품 데이터를 바꾸면 별도 새 진행으로 시작합니다. 이전 순차 방송 버전과는 저장 형식이 달라 진행을 가져오지 않습니다.
최근 수신 기록은 최대 200개를 보존합니다. 그 이전의 완료 조건과 수집품은 유지됩니다.

`node tests/engine.test.js`로 검증합니다. 가중치 경계, 선행 조건, 천장 강제 및 동시 도달, 트리거, 정지, 배속, 저장과 수집품을 검사합니다.

수정 파일: `events.js`(콘텐츠/설정), `engine.js`(규칙), `app.js`(화면 연결), `index.html`/`style.css`(화면).

## 창가 디자인과 시간대

플레이어는 방송을 듣는 수사관입니다. 평범한 도시가 보이는 사무실 창가와 작은 라디오, 화분, 머그잔, 서류철을 SVG/CSS로 그립니다. 방송국 멤버들의 메모와 폐허는 배경에 표시하지 않습니다. 방송 도착 후 행동을 선택하기 전까지 라디오 옆에 세 개의 소리선이 표시됩니다. 실제 오디오는 재생하지 않습니다.

`dist/sky.js`는 기기의 현지 시각을 사용합니다. 새벽 05–08시, 낮 08–16시, 노을 16–19시, 밤 19–05시로 창밖 하늘을 바꾸고 30초마다, 탭에 돌아올 때 갱신합니다. 실제 일출·일몰 시각이나 날씨 API는 사용하지 않으며 여우비 연출은 유지됩니다. 줄어든 동작을 설정한 기기에서는 비·음표 애니메이션이 멈춥니다.

## 수집품으로 창가 바꾸기

`dist/room-config.js`의 `roomRules`를 편집하세요. 게임 이벤트나 수집품의 기존 데이터는 바꾸지 않아도 됩니다. 현재 예시: `item-01` 획득 시 오른쪽 스탠드 표시.

```js
{
  id: 'my-decoration',
  requiresItems: ['수집품-id'],
  show: ['desk-lamp', 'books'],
  accent: '#94b8b3',
}
```

`requiresItems`에 적힌 수집품을 모두 보유해야 적용됩니다. 여러 규칙을 함께 만족하면 소품을 모두 표시하고, 강조색은 마지막 규칙을 따릅니다. `accent`는 생략할 수 있으며 6자리 HEX 색상을 사용합니다. 준비된 소품은 `desk-lamp`(스탠드), `books`(책), `photo-frame`(사진 액자), `glass-vase`(유리 화병)입니다. 소품의 도형은 `index.html`의 `data-room-decoration` SVG 그룹에서 수정합니다.

획득 직후, 새로고침 저장 복원, 진행 리셋 시 창가도 즉시 갱신합니다. 방 꾸미기 규칙만 수정하면 기존 게임 저장은 초기화되지 않습니다. `room-config.js`는 스타일 규칙이므로 수집품 정의나 진행 저장 형식과 분리되어 있습니다.

화면은 차콜·네이비 기반이며 라디오는 창가 왼쪽에 있습니다. 방송 중에는 말풍선과 음표 대신 라디오 옆 세 개의 소리선이 표시됩니다.

## 이벤트에 이미지 넣기

`dist/images/`에 이미지 파일을 업로드한 뒤 `dist/events.js`의 이벤트에 아래 필드를 추가하세요. 이미지가 필요 없는 이벤트는 생략하세요.

```js
image: {
  src: 'images/event-01.webp',
  alt: '이미지 내용 설명',
  fit: 'contain', // 전체 표시. cover는 영역을 채우며 일부가 잘릴 수 있습니다.
  caption: '이미지 아래 설명', // 생략 가능
},
```

`src`에는 HTTPS 이미지 주소도 사용할 수 있습니다. GitHub Pages 내부 파일은 `/images/` 대신 `images/`처럼 상대 경로를 쓰세요. 이미지가 로딩되지 않아도 오류 안내만 표시하고 행동 선택은 계속 가능합니다. 이벤트 정의를 수정하면 기존 규칙대로 새 진행으로 시작합니다.

라디오는 색감이 있는 SVG로 변경해 작은 화면에서도 주파수와 노브가 같은 비율로 표시됩니다. FM 표시는 제거했습니다. 소품은 창턱 y=560을 기준으로 놓았고 책은 서류철 위에 포갭니다. 비는 창문 영역 안에서 두 겹의 빗줄기로 빠르게 쏟아집니다.

## 라디오 색상 설정

수신 설정 → 라디오 컬러 파츠에서 외장 케이스·테두리·손잡이 색상을 `#RRGGBB`로 입력하거나 색상표로 선택하세요. 변경은 미리보기로 반영되고 **설정 적용**을 눌러 저장합니다. 적용하지 않고 창을 닫으면 이전 저장 색상으로 돌아갑니다. 기본색 버튼도 적용을 눌러 저장하세요.

색상은 게임 진행과 분리해 브라우저에 저장하므로 진행 리셋이나 이벤트 데이터 변경으로 초기화되지 않습니다. 스피커 메시·표시창·버튼은 고정색을 사용하며 외장 색상 변경에 영향을 받지 않습니다. 낮에는 햇살과 창턱의 빛, 밤에는 별이 표시됩니다. 구석의 날씨 설명 문구는 제거했습니다.

라디오는 둥근 외장과 일체형 전면 패널의 현대적인 탁상형입니다. 이전 색상 저장의 본체색은 유지하지만, 기존 스피커·버튼·표시창 색상은 더 이상 적용하지 않습니다. 외장 테두리와 손잡이는 새 설정값으로 조절하세요. 소품은 공통 광원 방향의 그라데이션, 옆면, 접지 그림자로 깊이를 표현합니다. 책은 서류철 위, 화병·스탠드·머그잔·액자는 각 자리에서 창턱에 닿게 배치합니다.

## 선택에 따른 이벤트 재등장 금지

행동 선택지에 `disableEvent: true`를 추가하면 그 행동을 고른 뒤 **해당 이벤트 전체**가 다시 나오지 않습니다. 다른 행동을 고르면 계속 등장할 수 있습니다.

```js
choices: [
  { id: 'listen', text: '더 듣는다', result: '다음에도 만날 수 있다.' },
  { id: 'finish', text: '연락을 마친다', result: '이 방송은 다시 나오지 않는다.', disableEvent: true },
],
```

기존 이벤트 옵션 `once: true`는 어떤 행동을 고르든 재등장하지 않는 설정입니다. `disableEvent`는 특정 행동만 지정합니다. 선택 완료 기록에 저장되므로 새로고침해도 유지되며 진행 리셋으로 해제됩니다. 천장보다 재등장 금지가 우선합니다.

## 날짜·시간대에 따른 등장 제한

이벤트에 `availability`를 추가하세요. 생략하면 언제나 등장 가능합니다. 시간은 **플레이어 기기의 현지 달력과 시각**이며 게임 내 시간이나 서버 UTC 시간이 아닙니다.

```js
availability: {
  dates: ['2026-12-24', '2026-12-25'], // 이 날짜들 중 하나. 생략 가능
  timeRanges: [
    { start: '18:00', end: '23:00' },
  ],
},
```

날짜 범위를 지정하려면 다음처럼 씁니다. 시작일과 종료일 모두 포함합니다.

```js
availability: {
  dateRange: { start: '2026-10-17', end: '2026-10-31' },
  timeRanges: [{ start: '22:00', end: '05:00' }],
},
```

- 날짜: `YYYY-MM-DD`, 시간: `HH:MM`. `end`에는 `24:00`도 가능합니다.
- 시간 구간은 **시작 포함, 종료 제외**입니다. 09:00–12:00이면 12:00부터 등장하지 않습니다.
- 22:00–05:00처럼 자정을 넘길 수 있습니다. 날짜는 그 순간의 달력 날짜로 판정하므로 새벽은 전날이 아닌 오늘 날짜의 조건을 따릅니다.
- 여러 `timeRanges` 중 하나를 만족하면 됩니다. 날짜 목록, 날짜 범위, 시간대를 함께 쓰면 모두 충족해야 합니다. 같은 시작·종료 시각은 오류로 처리합니다. 온종일은 시간대를 생략하거나 00:00–24:00을 쓰세요.
- 시간 밖에서는 유효 가중치가 0이며, 시간 안에서는 기존 가중치로 복원됩니다. 천장 이벤트도 시간 제한과 선행 조건을 지킵니다.
- 추첨하는 순간의 시각을 사용합니다. 이미 표시된 이벤트는 시간이 지나도 사라지지 않습니다.
- 시간 조건 때문에 후보가 없으면 종료하지 않고 다음 쿨타임에 다시 확인합니다. 방송이 나오지 않은 회차에는 등장 횟수와 천장 카운트를 소비하지 않습니다. 지나간 날짜만 남아 있는 경우에도 시간 대기를 유지하므로 다음 이벤트를 추가하거나 진행을 리셋할 수 있습니다.
- `events.js`의 주석에 복사해서 쓸 수 있는 예시가 있습니다. 실제 날짜 제한은 켜두지 않았습니다. 이벤트 정의 변경 시 새 진행으로 시작하는 기존 저장 규칙을 유지합니다.

## 비선택형(관람) 이벤트

이벤트에 `type: 'observation'`을 지정하고 `choices`는 생략하세요. 방송과 이미지가 표시된 뒤 **실제 10초**가 지나거나 **계속 듣기** 버튼을 누르면 완료되고 다음 방송 쿨타임이 시작됩니다.

```js
{
  id: 'quiet-broadcast',
  type: 'observation',
  weight: 3,
  title: '잠깐의 음악',
  text: '라디오에서 조용한 음악이 흘러나온다.',
  onComplete: {
    result: '음악을 끝까지 들었다.',
    // grantItems: ['item-01'],
    // startPity: ['broadcast-03'],
    // disableEvent: true,
  },
},
```

- `onComplete`는 생략할 수 있습니다. 수집품 획득, 천장 시작, 재등장 금지를 이곳에 지정합니다. 자동 완료와 버튼 완료는 같은 효과를 한 번만 실행합니다.
- 완료 시 `completedEvents`에 기록되므로 다른 이벤트의 `requires.events` 선행 조건을 해금합니다. 행동을 고르지 않으므로 `completedChoices`에는 가상의 선택지를 추가하지 않습니다.
- 기존 가중치·날짜/시간 제한·이미지·천장·`once` 옵션을 함께 사용할 수 있습니다. 관람 이벤트에 `choices`를 넣으면 설정 오류로 처리합니다.
- 설정·수집품 창이나 수동 일시정지 중에는 관람 타이머가 멈춥니다. 수동 정지 중에는 계속 듣기도 잠깁니다.
- 라디오 **쿨타임 배속과 관계없이 관람은 10초**입니다. 배속은 관람 후의 다음 방송 대기부터 적용됩니다.
- 새로고침하면 남은 시간을 이어 갑니다. 일반 관람 중 탭을 닫았다가 10초 후 돌아오면 그 방송 하나만 완료되며 다음 방송은 새 쿨타임을 기다립니다. 일시정지 중에는 남은 시간이 보존됩니다.
- 지금 표시된 방송은 날짜·시간 조건이 바뀌어도 관람을 마칠 수 있습니다. 이벤트 정의를 수정하면 새 진행으로 시작하는 기존 저장 규칙을 유지합니다.

## 현재 방송: 오프닝

견본 이벤트를 제거하고 `opening`을 첫 방송으로 등록했습니다. 가중치 100의 비선택형이며 10초 또는 “라디오의 오프닝에 귀를 기울인다” 버튼으로 완료합니다. `once: true`로 재등장하지 않고, `mustSeeFirst: true`로 미완료 상태에서는 일반 추첨·천장보다 먼저 등장합니다. 나중에 다른 이벤트를 추가해도 이 우선순위가 유지됩니다. 날짜·선행 조건·가중치 0 같은 등장 제한은 필수 우선 방송에도 적용되며, 오프닝에는 그런 제한을 두지 않았습니다.

관람 버튼 문구는 이벤트의 `continueText`로 지정합니다. 생략하면 기존 “계속 듣기 →”를 사용합니다. 오프닝 완료 후에는 반복 방송인 “고양이 블루스”를 청취할 수 있습니다. 이벤트 정의가 바뀌었으므로 이전 견본 이벤트 진행과 별도로 새 진행을 시작하며, 라디오 외장 색상 설정은 유지합니다.

## 청취 기록 전용 설명

이벤트의 `logDescription`으로 청취 기록의 설명을 따로 지정합니다. 실제 방송 본문 `text`와 완료 효과의 `onComplete.result` 또는 행동 `result`는 별도로 유지됩니다. 설명을 생략하면 기존 완료 결과를 표시합니다.

```js
logDescription: "처음으로 들어본 오프닝. 종말이라는 말과 달리, '팰리스'라는 자는 발랄하다.",
```

이 필드만 바꾸면 진행을 초기화하지 않습니다. 새 기록에는 이벤트 id와 설명을 저장하며, 이전 형식의 오프닝 기록도 제목이 유일할 때 현재 이벤트 설명으로 표시합니다. 기록 설명은 최신 이벤트 설정을 따르므로 이미 남은 기록에도 반영됩니다.

라떼의 금빛 꽃은 커피 표면 범위에 맞춰 그리며, 김은 세 갈래로 천천히 올라옵니다. 동작 줄이기 설정에서는 김을 정지된 형태로 표시합니다.


## 특정 선택 후 재등장 시 비선택형으로 전환

선택지에 `observationOnRepeat: true`를 지정하면 **그 선택을 완료한 뒤 해당 이벤트가 다시 등장할 때부터** 비선택형으로 전환합니다. 지정하지 않은 선택지는 기존 선택형을 유지합니다. 아래는 작성 예시이며 실제 방송 목록에는 추가하지 않았습니다.

```js
{
  id: 'night-music',
  tags: ['일상', '음악'],
  weight: 10,
  title: '밤의 음악',
  text: '라디오에서 익숙한 선율이 들린다.',
  choices: [
    { id: 'listen', text: '앞으로 조용히 감상한다', result: '다음부터는 음악에 귀를 기울이기로 했다.', observationOnRepeat: true },
    { id: 'answer', text: '방송에 응답한다', result: '짧은 인사를 전했다.' },
  ],
  continueText: '음악을 끝까지 감상한다',
  onComplete: { result: '음악을 감상했다.' },
},
```

- 첫 선택의 결과와 효과는 즉시 한 번 적용하고, 전환 후에는 원래 선택지 버튼을 표시하지 않습니다. 본문·제목·이미지는 그대로 사용합니다.
- 이후에는 실제 10초 또는 `continueText` 버튼으로 완료합니다. 비선택형의 일시정지·저장 복원·배속 규칙도 그대로 적용합니다.
- `onComplete`는 전환 후 감상 완료 시에만 적용합니다. 생략 가능하며 `result`, `grantItems`, `startPity`, `disableEvent`를 지원합니다. 원래 선택지의 효과를 다시 실행하지 않습니다.
- 전환은 선택 완료 기록을 사용하므로 새로고침 후에도 유지되고 진행 리셋 시 해제됩니다.
- `once: true` 또는 선택지의 `disableEvent: true`를 함께 쓰면 재등장 금지가 우선하므로 전환된 방송을 다시 만날 수 없습니다. `onComplete.disableEvent: true`는 전환 후 첫 감상이 끝났을 때 재등장을 막습니다.
- 가중치·선행 조건·날짜/시간·천장 규칙은 전환 후에도 유지됩니다. `observationOnRepeat`는 true/false만 허용합니다.

## 이벤트 내부 태그

이벤트의 `tags: ['일상', '음악']`으로 내부 분류를 지정합니다. 생략하거나 빈 배열로 둘 수 있으며, 비어 있지 않은 문자열을 중복 없이 작성합니다. 태그는 플레이 화면에 표시되지 않으며 등장 확률이나 조건을 바꾸지 않습니다.

```js
const musicEvents = events.filter(event => event.tags?.includes('음악'));
```

태그는 대소문자를 구분하는 정확한 문자열로 비교합니다. 태그만 추가·변경·삭제해도 기존 진행을 유지합니다. 현재 오프닝에는 `tags: ['오프닝']`을 지정했습니다.
